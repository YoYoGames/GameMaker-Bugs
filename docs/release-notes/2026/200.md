# GameMaker 2026.200.0 Beta

IDE 2026.200.0.1217 and runtime 2026.200.0.1145, updated 27 November 2026.

Downloads: [Windows](https://gms.yoyogames.com/GameMaker-Installer-2026.200.0.1217.exe) - [macOS](https://gms.yoyogames.com/GameMaker-2026.200.0.1217.pkg) - [Ubuntu](https://gms.yoyogames.com/GameMaker-Beta-2026.200.0.1217.deb)

## IDE

### Highlights

- **Code Editor 2: over 100 fixes**, covering selection, find and replace, indentation, completion, tooltips, colouring, folding, split views and performance in large scripts (see below).
- **Terminal window.** *Views > Terminal* opens your shell inside the IDE, docked with the Output windows and starting in the project folder: PowerShell on Windows, your login shell on macOS and your shell on Linux. Full-screen programs such as vim, htop and less work, including the mouse wheel, and Ctrl+click (Cmd+click on macOS) opens file paths, `file:line` locations, URLs and asset names.
- **Colour and links in the Output windows.** The Output windows show the colours from tool output, and you can add your own highlight rules. Ctrl+click (Cmd+click on macOS) a compile or runtime error location to open it in the code editor, or an asset name to open the asset. A bar counts the errors and warnings, F8 and Shift+F8 jump between them, you can filter the output to some text or to errors only, and you can export or copy it as HTML with its colours.
- **New theme system and a Dracula skin.** Every colour in the IDE now comes from the skin. Dark and Light look the same as before, except that Code Editor 2 now follows the skin and is light in the Light skin ([#5222](https://github.com/YoYoGames/GameMaker-Bugs/issues/5222)). Dracula is included as a built-in skin.
- **Skin Generator.** *Preferences > Skin Generator* lets you build your own IDE skin without editing theme files. Pick a background, text and accent colours, or go further and edit the grey ramp and syntax colours. You can start from Dark, Light, Dracula or a skin you made earlier. Skins can be imported and exported, and applying one doesn't need a restart.
- **Feather:** a new warning, GM1065, for calls to functions and constructors that don't exist ([#14226](https://github.com/YoYoGames/GameMaker-Bugs/issues/14226)), plus many type and completion fixes.
- **Markdown preview zoom** for Notes: Ctrl+mouse wheel (Cmd on macOS), the text size hotkeys or the right-click menu. Its zoom is separate from the code editor's and is remembered ([#5223](https://github.com/YoYoGames/GameMaker-Bugs/issues/5223)).
- **Stop only stops your own game.** Stopping a game, or closing the IDE, used to end every build tool, game, web server and adb process on the machine with a matching name, including ones started by another IDE. It now ends only the processes this IDE started.
- **Projects ask before upgrading files.** Opening a project no longer rewrites any files. If a project's files need upgrading to a newer format, the IDE tells you how many resources will change and lets you choose Upgrade or Cancel, so you can commit your work first and then commit the upgrade on its own.

### Code Editor 2

- Two clicks a second or more apart are no longer treated as a double click.
- Arrow keys no longer sometimes send the caret to the top of the document ([#15216](https://github.com/YoYoGames/GameMaker-Bugs/issues/15216)), and an empty selection no longer does either ([#15347](https://github.com/YoYoGames/GameMaker-Bugs/issues/15347)).
- All caret keys now come from *Redefine Keys*, and column selection is Shift+Alt again ([#12479](https://github.com/YoYoGames/GameMaker-Bugs/issues/12479)).

Cmd+, opens Preferences from the code editor ([#9097](https://github.com/YoYoGames/GameMaker-Bugs/issues/9097)).
- AltGr no longer triggers the Alt navigation shortcuts ([#7593](https://github.com/YoYoGames/GameMaker-Bugs/issues/7593)).
- Box selection: you can type while the mouse is still held, pressing Alt mid-drag works, and a new box selection replaces the previous one and its cursors ([#13455](https://github.com/YoYoGames/GameMaker-Bugs/issues/13455), [#11301](https://github.com/YoYoGames/GameMaker-Bugs/issues/11301), [#6998](https://github.com/YoYoGames/GameMaker-Bugs/issues/6998)).
- Drag-selecting from below the last line, and Shift+click below it, now select as expected ([#6752](https://github.com/YoYoGames/GameMaker-Bugs/issues/6752), [#7090](https://github.com/YoYoGames/GameMaker-Bugs/issues/7090)).
- Ctrl+Up/Down scroll the view in the direction the caret moves ([#5992](https://github.com/YoYoGames/GameMaker-Bugs/issues/5992)), and Page Up/Down keep going across all of an object's events ([#9503](https://github.com/YoYoGames/GameMaker-Bugs/issues/9503)).
- Duplicate with part of a line selected puts the copy straight after the selection ([#13933](https://github.com/YoYoGames/GameMaker-Bugs/issues/13933)).
- Join Lines drops the joined line's indentation ([#14196](https://github.com/YoYoGames/GameMaker-Bugs/issues/14196)).
- Commenting a selection keeps the caret and selection where they were, and comments every line at the same column ([#11589](https://github.com/YoYoGames/GameMaker-Bugs/issues/11589), [#11588](https://github.com/YoYoGames/GameMaker-Bugs/issues/11588)).
- Emoji are typed whole and count as one column, and the caret and Backspace step over ligatures correctly ([#7368](https://github.com/YoYoGames/GameMaker-Bugs/issues/7368), [#8740](https://github.com/YoYoGames/GameMaker-Bugs/issues/8740)).
- One undo takes back IME input ([#6084](https://github.com/YoYoGames/GameMaker-Bugs/issues/6084)), and undo removes the padding spaces added when typing past the end of a line ([#11303](https://github.com/YoYoGames/GameMaker-Bugs/issues/11303)).
- Clicking past the end of a line places the caret at the right column ([#9185](https://github.com/YoYoGames/GameMaker-Bugs/issues/9185)).
- No more ghost characters around × and ÷ between numbers ([#11528](https://github.com/YoYoGames/GameMaker-Bugs/issues/11528)).
- A child object's inherited events are read-only as soon as it opens ([#11738](https://github.com/YoYoGames/GameMaker-Bugs/issues/11738)). Using Peek Definition on an object event no longer changes whether that event can be edited elsewhere, so a parent object's event no longer becomes read-only and a child's inherited event no longer becomes editable ([#16458](https://github.com/YoYoGames/GameMaker-Bugs/issues/16458)).

- Types:
  - Passing a struct to a typed parameter no longer retypes the variable ([#16272](https://github.com/YoYoGames/GameMaker-Bugs/issues/16272)).
  - A base method that returns `self`, called on a child struct, gives the child's type ([#13504](https://github.com/YoYoGames/GameMaker-Bugs/issues/13504)).
  - `Ctor.method = function() {}` adds a static method to the constructor ([#15199](https://github.com/YoYoGames/GameMaker-Bugs/issues/15199)).
  - Expression variable definitions get the type of their value ([#6166](https://github.com/YoYoGames/GameMaker-Bugs/issues/6166)).
  - A parent constructor's errors are no longer copied into its children ([#5426](https://github.com/YoYoGames/GameMaker-Bugs/issues/5426)).
  - `@context` accepts a type in braces ([#6886](https://github.com/YoYoGames/GameMaker-Bugs/issues/6886)).
- Completion:
  - Completion works after chained calls, including function literal arguments and one call per line ([#12064](https://github.com/YoYoGames/GameMaker-Bugs/issues/12064)).
  - Macros are offered at a struct literal's key, and `nameof(x)` works as a key ([#14281](https://github.com/YoYoGames/GameMaker-Bugs/issues/14281), [#11875](https://github.com/YoYoGames/GameMaker-Bugs/issues/11875)).
  - A plain function's statics are no longer offered as globals ([#10281](https://github.com/YoYoGames/GameMaker-Bugs/issues/10281)).

## Runtime

### Highlights

- **The compiler and the runtime now agree.** Expressions the compiler works out ahead of time now give the same result as when they run, and many more built-in functions with constant arguments (string, hashing, colour and maths functions) are worked out at compile time ([#16191](https://github.com/YoYoGames/GameMaker-Bugs/issues/16191), [#14968](https://github.com/YoYoGames/GameMaker-Bugs/issues/14968)).
- **Mistakes that went unnoticed are now errors.** Writing to an argument that wasn't passed, multiplying a string by a number, returning an unset variable in YYC, and `var x = x;` used to fail silently or corrupt other code. They now report an error (see below).
- **`room_get_info` can return instance variables.** A new optional 8th argument, `variables`, gives each instance a `variables` struct with the values set in its pre-create event and its instance creation code ([#15764](https://github.com/YoYoGames/GameMaker-Bugs/issues/15764)).
- **OpenGL fixes for macOS and the other OpenGL platforms:** faster text drawing, no more corrupted text and vertex buffers, and fixes for multiple render targets, fog and alpha test in user shaders, and shader compile errors.
- **Non-rectangular viewports (experimental).** The new `view_set_viewport()` function draws a view through a polygon shape instead of a rectangle, and maps mouse and touch positions to the view whose shape contains them (see below).

### Behaviour changes

These may change what an existing project does:

- On the VM and YYC, writing to an argument that wasn't passed to a function (for example `argument3` when only two were passed) is now an error: "Unable to set argumentN, argument is not provided to the function". It used to overwrite the caller's values, which could make a `repeat` loop run forever ([#15992](https://github.com/YoYoGames/GameMaker-Bugs/issues/15992)).
- Multiplying a string by a number is now an error in YYC and HTML5, as it is on the VM. Multiplying a negative number by a string no longer crashes the game without a message ([#16192](https://github.com/YoYoGames/GameMaker-Bugs/issues/16192)).
- YYC: a function that returns a variable that was never set now reports an error ([#15991](https://github.com/YoYoGames/GameMaker-Bugs/issues/15991)).
- Using a variable in its own `var` declaration (such as `var x = x;` or `var x = x + 1;`) is now a compile error, unless it is already a local variable ([#15631](https://github.com/YoYoGames/GameMaker-Bugs/issues/15631)).
- A `#macro` whose name isn't a valid identifier (such as a string, a number or a reserved word like `if`) now stops the build with an error. It used to be silently dropped. This includes macros for other configurations.
- The Image Loaded async event now gives the id of a sprite made with `sprite_add_ext` as a sprite reference, not a number ([#4328](https://github.com/YoYoGames/GameMaker-Bugs/issues/4328)).
- `part_system_get_info` returns an empty `emitters` array, not 0, for a particle system with no emitters ([#6450](https://github.com/YoYoGames/GameMaker-Bugs/issues/6450)).
- [HTML5] Setting a struct or instance variable with an empty name (for example with `s[$ ""] = 1`, `struct_set()`, `variable_struct_set()` or `struct_set_from_hash()`) now throws the error "illegal to use empty names", as it does on other platforms, instead of quietly creating a `""` key ([#16400](https://github.com/YoYoGames/GameMaker-Bugs/issues/16400)).

### GML and the compiler

- Values worked out at compile time now match the runtime. At run time, on every target ([#16191](https://github.com/YoYoGames/GameMaker-Bugs/issues/16191)):
    - a real `div` an int64 gives a real;
    - `-` of a boolean gives a real (-1 or -0);
    - shift counts wrap at 64 bits (32 for 32-bit values);
    - a comparison with NaN is never equal;
    - a boolean compared with a string compares the string as a number;
    - `chr()` of a negative number, a number above 0x10FFFF or a surrogate gives an empty string;
    - YYC: `div` by zero is an error, and `div` gives an integer only when both sides are integers.
- More built-in functions with constant arguments are worked out at compile time, and the ones that already were now give the runtime's result ([#14968](https://github.com/YoYoGames/GameMaker-Bugs/issues/14968)):
    - strings: `string_copy`, `string_delete`, `string_count`, `string_pos_ext`, `string_last_pos`, `string_last_pos_ext`, `string_ord_at`, `string_trim`, `string_trim_start`, `string_trim_end`, `string_format`, `string_replace`, `string_replace_all`, `string_letters`, `string_digits`, `string_lettersdigits`, `string_length`, `string_byte_length`, and `string_upper` and `string_lower` for ASCII text;
    - hashing and Base64: `md5_string_utf8`, `md5_string_unicode`, `sha1_string_utf8`, `sha1_string_unicode`, `base64_encode`, `base64_decode`;
    - colours: `make_colour_rgb`, `make_colour_hsv`, `merge_colour`;
    - maths and types: `lerp`, `point_distance`, `dot_product`, `dot_product_3d`, `angle_difference`, `degtorad`, `radtodeg`, `frac`, `round`, `is_string`, `is_int32`, `is_callable`.
- A struct method with the same name as a built-in function (such as `abs`) is called when given a constant argument, instead of the built-in being worked out at compile time ([#16304](https://github.com/YoYoGames/GameMaker-Bugs/issues/16304)).
- A script function in a struct literal passed straight to a method or constructor no longer arrives as a number ([#16302](https://github.com/YoYoGames/GameMaker-Bugs/issues/16302)).
- A constructor that inherits from one that can't be found now gives a clear error ([#15656](https://github.com/YoYoGames/GameMaker-Bugs/issues/15656)).
- Converting NaN or a real that is out of range to a 32-bit integer gives the same result on every platform. It used to differ on ARM ([#16320](https://github.com/YoYoGames/GameMaker-Bugs/issues/16320)).

### Functions

- `room_get_info` has a new optional 8th argument, `variables` (default `false`). When it is `true`, each instance in the result has a `variables` struct with the values set in its pre-create event and its instance creation code. With the 7th argument, `live`, set, `room_get_info` now lists the room's instances as they currently are, with their current position, scale, angle, colour and image values (including instances created at runtime and deactivated instances, but no longer destroyed ones), and correctly reports layer `endScript`, text element `line_spacing` and `paragraph_spacing`, and tile and sequence `image_alpha`. [HTML5] On HTML5, `live` set to true now returns the current room, or a persistent room that has already been visited, as it currently is, including runtime changes to instances, layers and tilemaps, instead of always returning the Room Editor layout, and it no longer hangs on rooms that have a particle system on an asset layer ([#15764](https://github.com/YoYoGames/GameMaker-Bugs/issues/15764), [#16349](https://github.com/YoYoGames/GameMaker-Bugs/issues/16349)).
- `buffer_copy` no longer skips a source buffer that has nothing written to it ([#16308](https://github.com/YoYoGames/GameMaker-Bugs/issues/16308)).
- The new `buffer_utf8` data type reads or writes a single UTF-8 character as its code point. Malformed bytes read as U+FFFD (65533), and invalid values are written as U+FFFD. `buffer_read()` and `buffer_peek()` take an optional `size` argument, which reads exactly that many bytes as a string with `buffer_text` or `buffer_string` ([#16485](https://github.com/YoYoGames/GameMaker-Bugs/issues/16485)).
- Nine-slice sprites that are scaled get collision bounds that follow their repeat modes ([#13840](https://github.com/YoYoGames/GameMaker-Bugs/issues/13840)).
- `collision_point()`, `collision_point_list()`, `instance_position()`, `instance_position_list()` and `position_meeting()` test the pixel a point falls inside when checking against a Tile Map, as they do for instances, instead of rounding fractional positions to a neighbouring pixel (unless collision compatibility mode is on) ([#16423](https://github.com/YoYoGames/GameMaker-Bugs/issues/16423)).
- Collision functions such as `place_meeting()` and `collision_point()` check against the right tile masks on Tile Maps whose Tile Set uses tile separation ([#16420](https://github.com/YoYoGames/GameMaker-Bugs/issues/16420)).
- SVG and SWF sprites: fixes for sprites that could draw with the wrong cached image, and sprites tiled in one direction on a background layer now follow the layer's offset.
- DDS textures added with `texturegroup_add()` show the right mip levels and respect `gpu_set_tex_mip_enable()` being off. Uncompressed 32-bit RGBA and BGRA DDS data no longer crashes the game, and DDS data in a format the runner can't read now raises a GML error ([#16441](https://github.com/YoYoGames/GameMaker-Bugs/issues/16441)).
- Non-rectangular viewports (experimental): the new experimental function `view_set_viewport()` lets you draw any of the eight views through a polygon shape instead of a rectangle (concave shapes work), and set its port position and size and the area of the room it shows. The settings are passed as an array of structs or as a JSON string. Each view can also have optional start and end functions that run before and after it is drawn, for example to set and then reset a shader. Mouse and touch positions such as `mouse_x` and `mouse_y` are mapped to the view whose shape contains them. The function also works on HTML5. [HTML5] On HTML5, an empty `polygons` array that turns off a view's polygon during a Draw event no longer ends the game with an "Unbalanced surface stack" error, setting only some `roomRect*` fields no longer resets the others on the view's camera, fractional `roomRectX`, `roomRectY`, `roomRectW` and `roomRectH` values are kept instead of being rounded to whole numbers, so the view's camera gets the exact position and size you pass in, and odd-length or non-finite `polygons`, `screen*` and `roomRect*` values now give an error.

- [HTML5] In games seeded with `randomize()`, or with `random_set_seed()` with its second argument set to `true`, random functions no longer cause frame-time spikes and memory use that keeps growing the longer the game runs. Seeded random sequences in this mode may now differ from earlier versions ([#14435](https://github.com/YoYoGames/GameMaker-Bugs/issues/14435)).
- [HTML5] Sounds played in the same step now start exactly together, so layered music tracks and sounds meant to play in phase no longer drift a few milliseconds apart, and `audio_sound_get_track_position()` reports the position you actually hear.

### Code completion data

- GMRT's `collision_point_array`, `collision_rectangle_array`, `collision_circle_array`, `collision_ellipse_array` and `collision_line_array` are coloured and completed in the code editor, with parameter help ([#14943](https://github.com/YoYoGames/GameMaker-Bugs/issues/14943)).
- `handle_parse` returns Any ([#4630](https://github.com/YoYoGames/GameMaker-Bugs/issues/4630)).
- The structs returned by `part_system_get_info` and `particle_get_info` are described, so their members complete ([#6450](https://github.com/YoYoGames/GameMaker-Bugs/issues/6450)).
- Functions that take one of a set of constants, such as `tag_get_asset_ids`, list them ([#16345](https://github.com/YoYoGames/GameMaker-Bugs/issues/16345)).

### Building

- Building a game no longer changes any files in the project, such as the resource order file, files the build had tidied or upgraded, or effect prefab libraries in the project's local prefabs folder. Source control no longer shows unexpected edits after a build.
- A build stops with an error naming the extension and file when an extension file, or an entry in an extension zip set to uncompress, would be written outside the game's output folder. If a file in an extension zip can't be extracted, the build fails with an error after a few attempts instead of retrying forever.
- [Windows] Windows Smart App Control no longer blocks the libraries and bundled tools used to build a game on Windows, because these files are now signed ([#16444](https://github.com/YoYoGames/GameMaker-Bugs/issues/16444)).

### Stability

- Saving a buffer of size 0 no longer crashes the game ([#16219](https://github.com/YoYoGames/GameMaker-Bugs/issues/16219)).
- Games no longer crash on exit when a recognised controller is connected, for example a dual-port USB adapter that shows up as two gamepads with the same GUID on Ubuntu ([#16468](https://github.com/YoYoGames/GameMaker-Bugs/issues/16468)).
- Maps created by `ds_map_create()` with a size of zero or less (for example through `method()`) no longer crash the game or read and write memory outside the map.
- Assigning a number or other non-string value to `caption_score`, `caption_lives`, `caption_health` or `error_last` stores it as a string instead of crashing the game, and reading these variables repeatedly no longer corrupts memory and causes later crashes.
- [macOS] Games in a folder under `/private`, such as the system temp folder, no longer crash on startup. When the runner can't find or read the game, it now says why and ends the run, instead of crashing, waiting for someone to pick a file, or showing a Download panel that could crash when you quit it.
- [Ubuntu] Linux games no longer crash when they start the debugger or first use networking while a VPN tunnel, or another network interface without its own address, is active ([#16425](https://github.com/YoYoGames/GameMaker-Bugs/issues/16425)).
- [Windows] Windows games no longer crash on exit when an extension or another library has shut down Windows' COM system before the game closes.
- `sprite_delete()` on a sprite that `texturegroup_add()` made to replace one of the game's own sprites now restores the original sprite. Its name works with `asset_get_index()` again, a later `texturegroup_delete()` no longer crashes, `texturegroup_get_sprites()` no longer lists deleted sprites, and deleting one texture group no longer undoes another group's replacement of the same sprite ([#16449](https://github.com/YoYoGames/GameMaker-Bugs/issues/16449)).
